Check it before you trust it.

Palestinian internet users are targeted by fraud built specifically for the local context — fake Jawwal prize draws, cloned Bank of Palestine and PalPay login pages, delivery-fee scams, and "official" senders that are anything but. Aman is an Arabic-first web and mobile platform that lets anyone check a link, a message, an account, or a caller before acting on it — and report what they find so the next person is warned.

The problem

Generic scam filters don't speak the local language of fraud

International tools miss scams written in Palestinian Arabic, impersonating Palestinian brands, and referencing Palestinian payment rails. There was no local, Arabic-first place to ask a simple question: is this safe?

آمن · SafeNo known fraud indicator found — which is not the same as trustworthy.
مشبوه · SuspiciousSome indicators present. Verify through an official channel first.
خطير · DangerousStrong indicators. Don't click, don't pay, don't share codes.
Detection

Four checkers, one explainable verdict

Every check returns a 0–100 risk score and the reasons behind it, in Arabic and English. Nothing is a black box — a user can see exactly which signal fired.

URL checker

Local heuristics score a link before anyone visits it, then community reports and a check-frequency signal are folded in — a URL suddenly being checked by many people is itself evidence of an active campaign.

  • Lookalike domains for Palestinian brands (Levenshtein + substring)
  • Punycode, IP-literal hosts, and @ credential tricks
  • Suspicious TLDs, URL shorteners, keyword stuffing
  • Missing or invalid HTTPS

Message analyzer — and why "official" senders still get flagged

A weighted Arabic/English rule engine scores SMS and WhatsApp text, extracts any links, and runs them through the URL checker. Supplying the sender makes it sharper: a registered sender like JAWWAL normally reduces the score by 25.

But sender IDs are trivially spoofed. So when a message from an "official" sender asks for an OTP or carries a dangerous link, that reduction is withheld and a spoofing warning is raised instead — because a real bank never asks for your code.

Social accounts & callers

The same explainable scoring applied to two more surfaces users get targeted through: fake brand pages selling goods that never ship, and phone numbers behind prize-draw calls.

  • Handle impersonation, scam keywords, digit-suffix patterns (jawwal.prizes2026)
  • Platform detection across Facebook, Instagram, TikTok, Telegram, X, WhatsApp
  • A curated registry of genuine Palestinian senders — telecoms, banks, government
  • Phone normalization so 0599…, 00970… and +970… all match

Moderation dashboard

Nothing reaches the public unreviewed

Community data is only as good as its gatekeeping. Reports arrive as PENDING and are invisible everywhere until a moderator publishes them — the queue below is the only path from a submitted report to public search and the mobile blocklist.

Built to fail closed

The console is reached by URL and never linked from the site navigation. It is guarded by a shared secret compared in constant time, and the API refuses to operate at all unless that secret is configured — an unconfigured server rejects moderation rather than allowing it.

  • Token sent as a header, never in the URL where it would reach logs and history
  • Held in sessionStorage so it dies with the tab, unless "remember" is ticked
  • A rejected token is discarded immediately, so a bad secret can't loop
  • Queue is oldest-first, so no report starves

aman.ps/admin
Why this matters more than it looks. Approving a phone report doesn't just make it searchable — it propagates into /blocklist/phones, which every mobile install syncs for offline call and SMS screening. One moderator decision reaches every device.
Mobile

The same platform, plus protection that runs while you don't

The Flutter app carries every checker from the web. On Android it adds something the web cannot do: screening incoming calls and SMS as they arrive, entirely on the device.

A warning the moment the phone rings

The app syncs the approved-report blocklist to the device, then matches every incoming call and SMS against it natively — in Kotlin, without waking Dart. On a hit it draws a red bilingual warning card over whatever is on screen.

  • Nothing is uploaded. Calls and messages never leave the device
  • Nothing is blocked. The user is warned; the decision stays theirs
  • Matching is digits-only with a last-9 fallback, so 0599… matches +970599…
  • Works with the app closed; falls back to a heads-up notification if the overlay can't draw
Scam-call overlay
Blocklist synced on device
Why Android only — and why that is not a to-do item. iOS structurally forbids this. No app can read incoming SMS content (ILMessageFilter only sorts unknown senders into fixed folders, never returning the text), draw over other apps, or learn that a call arrived — CallKit matches a pre-supplied list that the system reads directly. The portable piece is that blocklist: iOS could block matches silently, with no verdict, score, or explanation. It is documented as a platform limitation, not left as unfinished work.
Arabic-first

Not an English app that was translated

Arabic is the default and the layout is RTL from the ground up, built on CSS logical properties so the entire interface mirrors correctly. English is a first-class toggle, not an afterthought — and every analyzer reason ships in both languages.

Architecture

One API, three clients, no vendor lock-in

Detection runs server-side so the rules improve for every client at once — with an optional local LLM as a bounded second opinion that can never override the rules.

Web React + Vite

  • TypeScript, React Router
  • 12 routes incl. the moderation console
  • Arabic-first RTL, ar/en toggle
  • 52 tests — vitest + testing-library

API Node + Express

  • Prisma ORM, Zod validation
  • Rule engines for URL, message, social, sender
  • Token-guarded moderation that fails closed
  • 85 tests — vitest

Mobile Flutter + Kotlin

  • Shared API client, same verdicts
  • Native call screening, SMS receiver, overlay
  • On-device blocklist store
  • 14 tests — flutter test

Data SQLite → PostgreSQL

  • SQLite in development, zero setup
  • PostgreSQL in production via Docker
  • Migrations applied before serving traffic
  • nginx serves the SPA and proxies the API
The optional LLM is deliberately on a leash. When a local Ollama model is reachable it gives a second opinion, but it can only move the score by ±25 and can never push a message the rules scored dangerous back below suspicious. If it is unreachable, times out, or returns malformed output, the analysis silently falls back to rules alone. No network dependency, no data leaving the machine.
